Orientation

What CCF6 is

CCF6 is a minimal, inspectable scientific instrument for testing computational consequences of Neurocognitive Linguistics. It is not a product, a natural-language system, or a claim of biological equivalence. The implementation sequence through GitHub issue #12 is complete; there are currently no open roadmap tickets.

Experiment definition

Python runtime

Runs ordinary Columns, local Eligibility, frozen observers, matched controls, and replication.

Artifact + workbench

Writes durable evidence to disk; Laravel validates and renders it without recomputation.
The workbench is read-only. Experiments are launched through the Python CLI or the runtime HTTP endpoint. The UI discovers run directories under artifacts/ and renders what the runtime already wrote.

Implementation record

What has been built

Issues #2–#12 form one progressive implementation. Each later experiment reuses the same declared domain and Network mechanics while adding an observer or stronger experimental control.

02

Synthetic lexical grounding

Four overlapping visual categories, reusable distributed auditory features, ordered three-segment pseudowords, balanced mismatches, deterministic generation, and isolated acquisition/basin/held-out splits.

03

Ordinary zero-rest Columns

Synchronous Input, Integration, and Output dynamics; exact zero rest; graded thresholds; sparse reciprocal endpoints; independent directional weights and Eligibility; explicit settling failures.

04

Coordinated Presentations

Visual activity first, then ordered auditory Samples. Activity persists within a Presentation and resets between Presentations. Reversed, permuted, repeated, and competing controls remain distinct.

05

Success-gated local learning

Eligibility accumulates from endpoint co-activity. Durable directional weights change only after a diffuse positive Success Signal, with local incoming normalization.

06

Recruitment and homeostasis

Entrenchment requires distinct successful Presentations. Threshold averages adapt locally and independently of success. Durable adaptation freezes for evaluation.

07

Matched Target Basins

Trained, identical untrained, and shuffled-pairing arms share initial conditions. Basin centroids, reliable masks, scales, distributions, and margins are fit without final held-out leakage.

08

Completion and reactivation

Full, visual-only, pseudoword-only, partial visual, and atypical cues are scored against frozen basins. Ordered trajectories are compared with every required sequence control.

09

Causal Functional Web observer

Membership requires reliability, completion perturbation, and reciprocal connectivity above matched controls with false-discovery-rate correction. Runtime activity never stores membership.

10

Cardinal causal classification

Observer-only Candidate and Cardinal Node gates, median-Output stimulation, Output Lesions preserving incoming observability, redundancy measures, and matched controls.

11

Replicated milestone

Twenty paired seeds, three arms per seed, 10,000 deterministic paired bootstrap resamples, seed-level effects, explicit failures, non-inferiority analysis, and one criterion-by-criterion verdict.

12

Complete artifact contract

The accepted ncl-functional-web-v1 contract is the default. Every required file is checksum-protected and independently validatable; superseded prototype code and compatibility paths are retired.

Local operation

Quick start with Docker Compose

The default ports are read from .env: workbench 8002, runtime API 8933, and Redis 6380. Internally, Laravel reaches the runtime at runtime:8931.

Prepare the application

From the repository root, create the environment, install PHP dependencies, initialize SQLite, and generate the Laravel key.

cp .env.example .env
composer install
touch database/database.sqlite
docker compose run --rm --no-deps php php artisan key:generate
docker compose run --rm --no-deps php php artisan migrate

Build and start the services

docker compose up -d --build
docker compose ps

The stack includes Caddy, PHP-FPM, the Python runtime, queue and schedule workers, and Redis.

Verify both interfaces

curl http://localhost:8933/health
open http://localhost:8002

On Linux, replace open with xdg-open, or enter the URL manually.

Run a fast experiment first

curl -X POST http://localhost:8933/run \
  -H 'Content-Type: application/json' \
  --data-binary @experiments/002-synthetic-lexical-grounding.json

Reload the workbench. A new run appears automatically because the runtime and Laravel share artifacts/.

Execution paths

Three ways to run an experiment

1. Runtime HTTP API

Best when the Docker stack is already running. POST /run is synchronous: the response arrives only after the artifact is complete.

curl -X POST http://localhost:8933/run \
  -H 'Content-Type: application/json' \
  --data-binary @experiments/008-completion-reactivation.json

The JSON response includes run, artifact, and summary. Use GET /health to see the runtime version and supported experiment kinds.

2. Python CLI on the host

Best for development and logs. The command prints the run directory and human-scale summary.

PYTHONPATH=ccf6-runtime/src python3 -m ccf6 \
  experiments/008-completion-reactivation.json artifacts

The host Python environment needs the runtime dependencies from ccf6-runtime/pyproject.toml, principally NumPy.

3. CLI inside the runtime container

Useful when the host has no suitable Python environment.

docker compose exec runtime python -m ccf6 \
  experiments/008-completion-reactivation.json artifacts

Validate without rerunning

The complete replicated artifact can be audited independently. Replace the directory with the run printed by the CLI or shown in the workbench.

PYTHONPATH=ccf6-runtime/src python3 -m ccf6 --validate \
  artifacts/011-<timestamp>-<digest>
The replicated milestone is intentionally substantial. Experiment 011 runs 20 seeds × 3 matched arms and stages thousands of Presentation records. Use experiments 002–010 for focused development before launching the complete run.

User interface

How to use the Laravel workbench

Runs index · /

Lists every artifact directory newest first, including experiment number, kind, status, duration, seed count, and digest. Select the experiment name to open its evidence.

Run view · /runs/{run}

Chooses the correct evidence view from the artifact manifest. The replicated view shows the complete contract, criterion verdicts, effect intervals, every seed, and failures.

Project documents · /docs/{page}

Renders root-level Markdown files in docs/. Examples: architecture, specification, and NCL summary.

For milestone artifacts, the workbench verifies the exact file inventory and SHA-256 checksums. Missing, malformed, unsupported, or modified artifacts are reported instead of interpreted through the current architecture.

Artifact identity

The digest changes when the definition, software version, generated dataset, or topology changes. Checksums detect any later file modification.

Database boundary

Numerical results never belong in SQLite. Artifacts are the source of truth; Laravel only reads them. The database is reserved for a catalogue if needed.

Safe experimentation

How to create a new declared run

Copy the nearest experiment

Start from the smallest definition with the behavior you need. Give it a new number, name, question, and—only if runtime dispatch changes—a supported kind.

Declare every result-affecting value

Seeds, topology, fan-in, initialization, dynamics, settling, learning, controls, observer thresholds, replication workers, bootstrap count, and non-inferiority margin belong in the definition. Unknown or malformed declarations should fail rather than silently default.

Protect the evidence boundary

Use acquisition and basin-estimation data to develop mechanisms and freeze observer definitions. Never select parameters by looking at final held-out performance. Preserve trained, identical untrained, and shuffled-pairing arms.

Run focused, then replicated

First verify mechanics and artifacts with one seed. Once the mechanism and analysis are fixed, execute at least 20 paired seeds and aggregate seed-level effects—not Presentations.

Keep negative results

Do not discard settling failures, seeds without Candidates, or hypotheses that fail. Record them in artifacts and let the workbench state the result plainly.

Operations

Troubleshooting

The workbench shows no runs
Run an experiment first and verify both services use the same artifact directory. Docker uses /www/artifacts in both containers. On the host, the default is the repository's artifacts/. Reload http://localhost:8002 after the run completes.
A run is “unsupported or malformed”
Read the message on the page. The manifest may use a retired contract, omit a required file, contain malformed JSON, or have a checksum mismatch. Do not edit a completed artifact to make it render; rerun its recorded definition with the current software when comparison is scientifically valid.
The runtime reports an unknown current experiment kind
If /health reports version 0.1.0 or lists only the retired colour_selectivity_baseline, the runtime container predates the NCL Functional Web implementation. Rebuild and recreate it with docker compose up -d --build --force-recreate runtime, then verify curl http://localhost:8933/health reports version 0.2.0 and the current experiment kinds.
The runtime health endpoint does not respond
Run docker compose ps and docker compose logs runtime. Confirm FORWARD_RUNTIME_PORT=8933 is free. Rebuild with docker compose up -d --build runtime after changing the image or package metadata.
The UI does not respond
Inspect docker compose logs caddy php. Confirm FORWARD_PHP_PORT=8002 and that Composer dependencies exist in vendor/. The public URL is controlled by APP_URL.
The runtime returns HTTP 500
The response contains a traceback because a failed run must be diagnosable. Common causes are invalid experiment declarations, settling failures in phases that require success, artifact permissions, or insufficient resources. Keep the definition and failure evidence.
Artifacts are owned by root or cannot be written
Set WWWUSER and WWWGROUP in .env to your host user and group IDs, then rebuild the services. The runtime container deliberately runs as those IDs.
The complete run is slow
Experiment 011 executes substantial numerical work. Its replication.workers value is declared in the experiment. Change it only as part of a new definition; the changed definition must produce a new identity. Use focused experiments while iterating.
Frontend changes are not visible
The current workbench views mostly use inline styles and do not require Vite. If bundled assets are changed later, run npm install and npm run build, or keep npm run dev active.

Forward path

Recommended next steps

Scientific

Decide the next local temporal mechanism

The first milestone localized a failure: broad co-activity saturates Eligibility and loses ordered conjunctions. The next proposal should introduce an NCL-compatible temporal distinction—such as sequence-local Eligibility, a declared WAIT-like recurrent configuration, or another local mechanism—without installing symbolic order or semantic labels.

Method

Predeclare development and evaluation

Write a new issue/specification before changing mechanics. Choose parameters using mechanics and development evidence only, freeze the decision, then rerun the same held-out cues, matched arms, web controls, cardinal interventions, and 20-seed inference.

Comparison

Treat the failed artifact as the baseline

Compare a new mechanism against the accepted run on saturation, Recruitment selectivity, completion, ordered reactivation, pairing localization, web overlap, cardinal causality, separation, and failures. Do not overwrite or reinterpret the baseline.

Usability

Add run submission only if needed

The current workbench intentionally reads artifacts and does not launch experiments. A future UI could submit an existing declared definition to the synchronous runtime endpoint while keeping experiment authoring and numerical computation out of Laravel.

Project boundary CCF6 remains a permanent minimal reference instrument developed independently. Do not consult or import CCF7 designs when choosing the next mechanism.

Domain and experimental language

Extensive glossary

These definitions combine the canonical NCL vocabulary in CONTEXT.md with the measurement, control, inference, and artifact terms used by the implemented experiments. Capitalized domain terms retain their project-specific meanings.

94 terms

NCL network organization

The entities and observer classifications used to describe the connected cognitive system.

Network
The complete connected cognitive system in which local functions arise from connectivity and activity; not a symbolic processor.
Column
The smallest addressable processing population. It stores no symbol or concept; its function comes from connectivity and activation history.
Population
A group of ordinary Columns receiving a related class of evidence and participating in one or more distributed functions.
Modality
The sensory or motor channel through which activity enters or leaves a Population, such as visual or auditory; not a cognitive function.
Functional Web
A distributed, overlapping coalition demonstrated by reliable co-activation, effective connectivity, completion from independent Entry Routes, and causal evidence. It is an observer result, not a runtime container.
Subweb
A functionally distinguishable part of a Functional Web that may also participate in other webs rather than being owned by one.
Entry Route
A functionally independent sensory, linguistic, conceptual, or motor path capable of contributing to a Functional Web's Ignition.
Available Column
A Column whose plasticity has not yet been committed to a recurring function.
Recruited Column
A Column measurably entrenched by repeated successful participation across distinct Presentations.
Cardinal Candidate
A Recruited Column or redundant population that passes independent-route, stability, stimulation, and matched-control gates. Recruitment alone is insufficient.
Cardinal Node
A Cardinal Candidate that demonstrates stable access, partial-cue Ignition, supporting-Subweb reactivation, Lesion sensitivity, redundancy behavior, and cross-seed evidence.
Reciprocal topology
Connected Population endpoints support both ascending and descending routes while each direction keeps independent weights and Eligibility.
Fixed latent topology
Abundant sparse connections are created before learning. Learning may alter their strengths but cannot add, remove, or redirect them in milestone one.
Input, Integration, Output
The three private functional compartments of every Column: incoming drive, recurrent/contextual competition, and graded broadcast response.

Activity, learning, and causal behavior

Terms for what the Network does during a Presentation and what may change durably afterward.

Activation
The graded current response of a Column or Population to excitation, inhibition, recurrence, threshold, and context; not a truth value.
Broadcast
Output activity sent to connected Columns when it meets the declared transmission cutoff. The cutoff does not alter stored Output.
Competition
Bounded local inhibition among alternatives that sharpens participation without imposing a global symbolic winner.
Persistence
Temporary maintenance of activity through recurrent connectivity; not permanent memory.
Eligibility
A bounded, decaying local trace on one directional connection. It marks co-activity that a later Success Signal may confirm.
Success Signal
A diffuse modulatory value indicating an observable successful outcome without identifying a category, Column, Population, or connection.
Recruitment
Experience-dependent commitment through eligible connections confirmed across distinct successful Presentations; never one tick or one Sample.
Entrenchment
Accumulated evidence of repeated successful use that increases a pathway's stability and accessibility.
Homeostasis
Local adaptation of each Column's activity average and threshold toward a declared target, independently of the Success Signal.
Ignition
Coordinated activation of a Functional Web from a sufficiently informative partial Entry Route.
Pattern Completion
Reactivation of absent parts of a learned Functional Web from partial evidence; not record retrieval.
Stimulation
A causal intervention that clamps selected Output to a declared amplitude, here derived from median full-Presentation activity, with sensory input absent.
Lesion
A causal intervention that clamps selected Output to zero while preserving observation of activity arriving at Input and Integration.
Redundancy
Preservation or recovery of function through alternative Columns or routes when one Candidate or Candidate group is lesioned.

Experimental domain and protocol

Terms that identify what is presented, when adaptation is allowed, and which evidence may be used.

World
The external arrangement presented to the Network during an experiment; not an internal model.
Object
A presentation target defined by externally observable parts or properties; not a stored concept.
Presentation
One ordered exposure of an Object or cue to the Network. Activity and Eligibility reset between independent Presentations.
Sample
One sensory observation within a Presentation. Activity and Eligibility persist from one Sample to the next.
Sensory adapter
A stateless mapping from distributed physical features to sensory Population activity. It carries no category identity, history, or outcome.
Acquisition
The phase in which balanced correct and mismatched visual–pseudoword Presentations may adapt weights, thresholds, entrenchment, and Recruitment.
Correct pairing
A category's declared visual evidence paired with its pseudoword; after successful settling it receives Success Signal 1.0.
Mismatch
A balanced visual–pseudoword control Presentation that receives Success Signal 0.0, showing that co-activity alone is insufficient.
Ordered pseudoword
A three-segment lexical form assembled from shared distributed auditory features and distinguishable by temporal conjunction rather than a unique feature.
Sequence control
A reversed, permuted, repeated-segment, or competing pseudoword trajectory used to test whether order—not only the feature bag—was learned.
Basin-estimation split
Four disjoint instances per category used to fit frozen basin centroids, scales, reliable masks, distributions, and margins.
Final held-out split
Four disjoint instances per category reserved for final evaluation and forbidden from influencing generation decisions, fitting, or parameter selection.
Partial cue
An incomplete Entry Route, such as a subset of visual properties, used to test movement toward the correct Target Basin and Pattern Completion.
Atypical held-out cue
A final held-out instance selected by the declared prototype-distance rule to test graded recognition away from the prototype.
Settling
Recurrent execution until the maximum Output change remains below the declared epsilon for the declared consecutive stable ticks.
Settling failure
Reaching max_ticks without stability. Recognition cannot be inferred, and the failure must be counted rather than discarded.
Durable adaptive state
Weights, thresholds, activity averages, entrenchment, contributor identities, and Recruitment evidence that survive activity reset. Fixed topology is durable but not adaptive.
Frozen evaluation
Basin estimation and final testing with every durable adaptive process disabled. Observation may not become additional training.

Plain-language experiment vocabulary

Short definitions for recurring words that appear throughout run definitions, evidence tables, and result discussions.

Basin
A region of Network activity toward which recurrent settling tends to converge. In these experiments, a category's measured and frozen region is its Target Basin.
Trace
A value or sequence that preserves how something changed over time. An Eligibility trace is temporary local connection state; an activity trace records Column activity across ticks. A trace is evidence, not a symbolic memory record.
Pseudoword
An invented, pronounceable experimental form with no pre-existing meaning. Here it is an ordered sequence of three reusable segments represented by distributed auditory features.
Centroids
The category-level mean activity vectors calculated from basin-estimation instances. Each centroid summarizes the center of one fitted Target Basin without storing any one Presentation as the target.
Scales
Per-Column variability values used to put activity differences on comparable units. The frozen pooled scales divide centroid differences in standardized Euclidean distance and cannot fall below minimum_scale.
Reliable masks
Frozen Boolean selections identifying which Columns are stable enough across basin-estimation instances to contribute to a category's primary basin distance.
Distributions
Recorded collections of observed or control values rather than one summary number—for example within-category distances, between-category distances, or random-coalition scores.
Margins
Frozen separation allowances derived from basin-estimation distributions. A correct basin distance must beat every competing distance by more than the category's margin.
Path
A concrete sequence of connected directional routes through which activity can propagate. A path is not itself an Entry Route: an Entry Route is a functionally independent source of access and may use several paths.
Arm
One matched experimental condition run from controlled initial conditions. The milestone uses trained, untrained, and shuffled-pairing arms for every seed.

Target Basins, controls, and observer evidence

Terms used to turn frozen Network activity into comparable recognition and causal measurements.

Target Basin
The stable distributed activity region approached during a full learned Presentation and estimated from several instances, never one stored vector.
Centroid
The mean settled activity vector of one category's basin-estimation instances.
Reliable-Column mask
The frozen subset of Columns whose basin-estimation variability remains within the declared stability limit.
Pooled scale
A per-Column variability estimate fitted from basin-estimation evidence and bounded below by minimum_scale.
Standardized Euclidean distance
The primary basin metric: root-mean-square centroid difference after division by frozen pooled scales over reliable Columns.
Cosine distance
A secondary directional-similarity diagnostic retained for inspection but never substituted for the primary standardized metric.
Basin margin
A frozen threshold derived from within-category basin-estimation distances. Correct distance plus margin must beat every competitor.
Trained arm
The matched arm that receives declared Success Signals and performs durable acquisition before evaluation is frozen.
Untrained arm
An otherwise matched Network that performs no durable learning, establishing what initial wiring alone can do.
Shuffled-pairing arm
A trained matched arm that changes only category–pseudoword pairings, testing whether effects localize to the correct arbitrary signs.
Matched control
A comparison selected to share all relevant initial conditions or nuisance properties except the intervention or hypothesis-bearing factor.
Pairing localization
The degree to which trained completion and reactivation exceed the shuffled-pairing arm rather than reflecting generic adaptation.
Reliability evidence
Category-conditioned activation consistency compared with shuffled-label control distributions.
Causal completion contribution
The change in completion caused by perturbing a Column, compared with matched random-Column perturbations.
Reciprocal effective connectivity
Measured two-direction connectivity within a proposed coalition, compared with degree-matched random coalitions.
False-discovery-rate correction
Benjamini–Hochberg correction across tested Columns that limits the expected proportion of false selections among discoveries.
Observer
Offline analysis that classifies basins, Functional Webs, or cardinals from recorded evidence without changing Network activity or learning.

Replication, inference, and results

Terms used by experiment 011 and the workbench to state what the evidence supports.

Seed
An integer that deterministically controls generated data, topology, initial weights, and random controls for one paired replicate.
Replicate unit
The independent unit used for inference. In the milestone it is the seed, never an individual Presentation.
Nested observation
A Presentation measured within a seed. It contributes to that seed's value but is not counted as an independent replicate.
Paired effect
A within-seed difference between matched arms or conditions, preserving shared data, topology, parameters, and initial state.
Deterministic bootstrap
Seeded resampling of paired seed effects—10,000 times in the milestone—to estimate the sampling interval of the median.
95% bootstrap interval
The 2.5th-to-97.5th percentile range of bootstrapped seed-level median effects. It is not computed over Presentations.
Expected-direction proportion
The fraction of seed effects above the declared target: zero for improvement effects or the negative margin for non-inferiority.
Failure count
The explicit number of unusable effects, settling failures, failed seeds, or non-executable required interventions associated with a result.
Non-inferiority margin
The largest acceptable degradation. Held-out category separation must have a lower interval bound above the declared −5% relative margin.
Criterion
One preregistered pass/fail condition in the milestone acceptance set, reported independently with its evidence.
Milestone verdict
The conjunction of all required criteria. One failed criterion makes the overall verdict fail even when another criterion passes.
Negative result
A completed, auditable experiment whose evidence does not support the tested hypothesis. It is not equivalent to a runtime error.
Conformance
Evidence that the apparatus implements the accepted specification. Conformance does not imply a positive scientific verdict.

Artifacts and workbench

Terms for reproducibility, identity, integrity, and display.

Experiment definition
The exact JSON declaration of the question, mechanism, parameters, controls, seeds, and analysis used by a run.
Run
One execution of an experiment definition, identified by experiment number, timestamp, and content-derived digest.
Artifact
An on-disk, rerun-free record of definitions, numerical arrays, Presentations, observer evidence, failures, and results.
Artifact contract
The required file inventory and field semantics. The accepted complete contract is ncl-functional-web-v1.
Manifest
The artifact index recording contract, software version, identity, timing, status, stimuli, parameters, ordered files, and checksums.
Digest
A compact content-derived identity that changes with result-affecting definitions, software, generated datasets, or topology.
Checksum
A SHA-256 integrity value for one artifact file, used to detect modification or corruption after the run.
Workbench
The read-only Laravel UI that validates and renders runtime-produced artifacts without rerunning experiments or recomputing scientific values.
